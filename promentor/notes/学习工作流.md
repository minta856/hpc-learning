## 二、三条硬规则（Ch 0 用血换来的）

### 规则 1：保存协议 —— **验证之前不要关窗口**

```
打完 → Ctrl + S → 看标题栏的 * 是否消失
     → 【不要关窗口】 → 说「存好了」
     → 我读磁盘确认 → 这时你才关窗口
```

- **标题栏有 `*` = 还没保存；`*` 消失 = 已保存**
- ⚠️ 记事本关闭时的弹窗**默认按钮常常是「不保存」**——**别用鼠标点右上角的 `×`**
- Ch 0 因此**白丢了一整轮**（"写完了" → 磁盘上文件一个字节都没变）

### 规则 2：**先看文件里有没有"给定部分"，再决定怎么改**

| 文件长什么样 | 怎么改 |
|---|---|
| 整个文件都是你要写的（我清空过的骨架） | 可以 `Ctrl + A` 全选重打 |
| 文件里有 `import` / `interface` / 注释 / 已给的类型 | **绝对不要全选！** 只改你要改的那几行 |

- Ch 0 的作业本有**三个 interface**（给你的），一次全选重打把它们删了 → 报
  `SyntaxError: Unterminated block comment`（注释的收尾 `*/` 也没了）→ 又白丢一轮

### 规则 3：整行替换用 `Home` → `Shift + End` → 直接打

- 比"按很多次退格删干净"可靠得多（下划线、占位符经常删不干净）
- 只改一行的某个词时：双击那个词选中再打，别整行重打

## 三、错误要分两类（这是学得快的关键）

| 类型 | 例子 | 说明 |
|---|---|---|
| **打字层** | `cont`→`const`、`addtask`→`addTask`、`tode`→`todo`、`[. . .`→`[...`、中文引号、`；`↔`：` | **懂了但手滑**。只能靠多打几遍，会自然减少 |
| **理解层** | 少一层 `if`（把"缺失=正常"和"存在但非法=错误"混成一件事） | **这才是真正要学的东西** |

**每章结束看一眼这个比例。** 你的历史数据：

| 章节 | 打字层 | 理解层 |
|---|---|---|
| mini-todo Ch 4 | 9 | **0** |
| mini-todo Ch 5 | 0 | **0** |
| mini-todo Final | 0 | **0** |
| 插件课 Ch 0 | 3 | **1**（少一层 if） |

> **打字层不为零 ≠ 没学会。** 只要理解层是 0，你的"懂"是真的，剩下的只是手上功夫。

## 六、代码是怎么跑起来的（运行工作流）

### 1. 一条命令

```powershell
cd "C:\Users\ubuntuuser\Documents\deepseek-harness\default-workspace"
node .promentor\chapters\ch00-plugin-anatomy\lab_test.ts
```

### 2. 从敲下回车，到看到 ✔/✖ —— Node 内部五步

```
node lab_test.ts
 ① Node 发现后缀是 .ts → 启用内置「类型擦除」：
      把 interface / `: string` / `as const` 删掉 → 得到等价的普通 JS
 ② 加载 lab_test.ts，执行它的 import：
      · node:test / node:assert/strict  ← Node 自带，不用装包
      · './plugin-anatomy.ts'           ← 你的文件，同样擦掉类型后加载
      · import type { ... }             ← 整行被删掉（类型在运行时不存在）
 ③ 逐个执行 test('名字', () => { ... })：注册一条、跑一条
 ④ 每条断言用 assert.equal / assert.deepEqual 检查 → 不满足就抛 AssertionError
 ⑤ 汇总：打印每个 ✔/✖ + ℹ tests/pass/fail，最后用 exit code 表态
      exit 0 = 全过     exit 1 = 有失败
```

### 3. 谁 import 谁（Ch 0 的依赖图）

```
lab_test.ts                                    ← 你不能改
 ├─ import { test }   from 'node:test'         ← Node 内置
 ├─ import assert     from 'node:assert/strict'← Node 内置
 ├─ import { describePlugin } from './plugin-anatomy.ts'   ← 你写的（值）
 └─ import type { PluginDescriptor } from './plugin-anatomy.ts'  ← 你写的（类型，运行时被删）
```

### 4. 为什么零依赖、无需构建

| 平常项目需要 | 这里为什么不需要 |
|---|---|
| `npm install` | 工作区里**没有 package.json / node_modules**，测试框架和断言都是 Node 自带的 |
| `tsc` 编译 | Node 24 **内置类型擦除**，`.ts` 直接跑 |
| vitest / jest | `node:test` 就是内置测试框架 |

**所以"跑测试"= 跑一个 `.ts` 文件。没有构建步骤，没有配置文件。**

### 5. 怎么读输出

```
✔ host 半边：清单没有 dsh.client 时 client 为 null (0.9ms)   ← 通过
✖ platform 非法：... (0.5ms)                                ← 失败
AssertionError: 期望 ...，得到 ...                            ← 失败原因（紧跟其后）
ℹ tests 11   ℹ pass 9   ℹ fail 2                            ← 汇总
```

### 6. 四种运行期报错，怎么分辨（**这张表最有用**）

| 报错 | 出现在哪个阶段 | 意思 | 先查什么 |
|---|---|---|---|
| `SyntaxError [ERR_INVALID_TYPESCRIPT_SYNTAX]` | **加载阶段**（测试一条都没跑） | 你的 `.ts` 语法坏了 | 引号/括号配对、`[. . .`（点之间有空格）、注释没关 |
| `ERR_MODULE_NOT_FOUND` | 加载阶段 | 找不到被 import 的文件 | 文件名、路径、`.ts` 后缀 |
| `AssertionError` | 跑用例时 | 文件读懂了，但**结果不对** | 看那句"期望 X，得到 Y" |
| `TypeError: xxx is not a function` | 跑用例时 | 调用了不存在的能力/名字拼错 | 拼写、`?.` |

> 🔑 **最重要的区分**：
> **`SyntaxError` = 文件根本没被读懂** → 11 条测试**一条都不会跑**（你会只看到一行红字）。
> **`AssertionError` = 文件读懂了，只是结果不对** → 你会看到 `pass 9 / fail 2`。
> 前者修语法，后者修逻辑——**先看有没有 `ℹ tests` 那一行，就知道自己在哪一类。**
