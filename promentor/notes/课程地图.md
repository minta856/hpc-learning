## 一、比喻：两块乐高 + 一条线

一个功能，拆成两半装：

- **后台那半（host）**：装在 Node 程序里，**能读你电脑上的文件**
- **浏览器那半（client）**：装在网页里，**能画界面**，但**碰不到你的文件**（浏览器没这个权限）

**为什么要拆？** 因为合成一块的话，浏览器那份代码里就会带上"读文件"的代码——
它在那里跑不了，而且**会悄悄坏掉**（面板一直转圈，不报错）。**隐蔽的坏，比崩溃难查一百倍。**

两块之间**只有一条细线**：

```
浏览器 ──"给我 .promentor/course.json"──▶ 后台 ──读文件──▶ 你的磁盘
```

**这条线是唯一入口。** 而线那头浏览器说的话是**不可信的**——
它完全可以说"给我 `..\..\Windows\System32\config`"。

> 所以：**线上必须站一个保安。**

## 三、为什么先学 mini-todo？

因为它是**同一个五步，但只有一个程序**：

| 五步 | mini-todo（一个程序） | 插件课（两个程序 + 一条线） |
|---|---|---|
| ① 造零件 | `title.js` / `task.js` | Ch 0：描述符（是哪一半） |
| ② 查和改 | `query.js`（`filter` / `summarize`） | Ch 2：数据层 |
| ③ 显示 | `render.js`（`renderList`） | Ch 4：视图 |
| ④ 存取 | `store.js`（读写 JSON） | Ch 1：网关 ＋ Ch 3：状态 |
| ⑤ 组装 | `cli.js` → `main.js` 跑通 | Ch 5 ＋ Final |

**这五步你在 mini-todo 里已经全走过了，而且 63 条测试全绿。**

所以插件课**不是新东西**——是**同一套五步，加了一个新维度**：

> **两个程序 + 一条不可信的线。**

## 四、脑子里只要记住这三句话

1. **一个插件 = 两块积木**：后台能读盘，浏览器能画界面，**互相碰不到对方的零件**
2. **两块之间只有一条细线**：所以**那条线上必须站保安**（这就是 Ch 1）
3. **每块积木内部，都是"小零件 + 测试"拼起来的**：这就是你在 mini-todo 练出来的本事
